## 1. 作业目标与整体流程

从浏览器摄像头取帧，检测所有达到置信度阈值的人脸，为每张脸生成线描肖像，从帽子库选择素材，随人脸位置、大小与倾斜变化进行佩戴，最后显示和保存。

统一处理链：原始帧 → YOLO 人脸框与五点 → 跨帧关联 → 平滑的裁剪与对齐 → 卷积生成线描 → 几何驱动的帽子合成 → 多人画面与个人卡片。

素描与帽子共享同一帧、同一裁剪变换和同一跟踪 ID。几何在原始照片上估计，不在生成的素描上重复检测。模型可能轻微改变局部形状，因此这种坐标复用是近似配准，需要观察实际偏差。

“所有人脸”是遍历全部有效检测，而非只处理最大脸；不能保证遮挡、极小脸也全部检出。人数增长时调整更新率或批处理，不静默丢弃其余人物。

## 2. YOLOv5 与 RT-DETR

| 方面 | YOLOv5 | RT-DETR |
| --- | --- | --- |
| 基本方式 | 多尺度特征图上的密集候选预测 | CNN 特征与高效混合编码器，再由查询驱动的 Transformer 解码器输出目标集合 |
| 候选组织 | 经典版本使用 anchor；多个候选可能对应同一目标 | 通过集合预测与训练时的一对一匹配减少重复 |
| 常见后处理 | 置信度筛选＋NMS | 标准推理流程不依赖 NMS，但仍需要阈值筛选 |
| 本次使用条件 | YOLO5Face 已有人脸专用模型与五点分支 | 官方常用权重是通用目标检测；需另外核实人脸权重 |
| 选择理由 | 任务匹配、权重与几何输出可直接复用 | 若后续关注 Transformer 检测或具备合适人脸权重，再考虑 |

不能简单说“CNN 只看局部，Transformer 看全局”：卷积层也能形成大感受野，RT-DETR 也包含卷积骨干。不能用论文中的特定 GPU 数字直接断言本机谁更快。

本次选 YOLOv5s-Face，依据是现成的人脸任务适配与实施成本，不是宣称 YOLOv5 在所有场景优于 RT-DETR。

来源：[YOLOv5 架构](https://docs.ultralytics.com/yolov5/tutorials/architecture-description/)、[RT-DETR 论文](https://arxiv.org/abs/2304.08069)、[RT-DETR 官方仓库](https://github.com/lyuwenyu/RT-DETR)。

## 3. YOLOv5s-Face 的产出

YOLO5Face 是在 YOLOv5 基础上针对人脸修改并训练的检测器。除人脸任务权重外，增加了五点回归头，并调整部分网络结构。s 表示较小规模；不要把家族中 s6 等版本的额外尺度结构一概归到 s 上。普通 YOLOv5 的 COCO 权重不能直接替代 Face 权重。

对每个通过筛选的检测，应用统一整理为：

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| bbox | 原始图像上的 x1、y1、x2、y2 | 定位、估计脸宽、扩展裁剪、关联 |
| score | 检测置信度 | 筛除不可靠候选 |
| landmarks5 | 双眼、鼻尖、两嘴角，共五个二维点 | 对齐、歪头角度、粗略定位 |
| trackId | 后续跟踪器赋予的编号 | 绑定帽子和连续状态，非检测网络直接输出 |

统一左右点的语义与镜像规则。原始网络张量包含大量候选，应用中的“每人一条记录”是解码、阈值和 NMS 后的结果，不硬编码不同导出格式的列顺序。

框负责“哪里有脸”；五点负责“脸内部怎样排列”。它们不提供头顶、头发轮廓或可靠的完整三维头部表面。

来源：[YOLO5Face 论文](https://arxiv.org/abs/2105.12931)、[代码与权重](https://github.com/deepcam-cn/yolov5-face)。

## 4. 平滑裁剪、对齐、关键点与姿态

### 4.1 平滑裁剪

检测框即使在人不动时也会抖。每帧直接按框缩放，网络输入会忽大忽小，生成线条和帽子也会闪。

先关联同一人物，再平滑中心、尺度和角度。基础方案是指数滑动平均：

$$
\bar c_t=\alpha c_t+(1-\alpha)\bar c_{t-1}.
$$

平滑的是几何参数，不是把连续照片混合。尺度可在对数域平滑；角度应考虑周期连续性。权重越小越稳，也越容易滞后，快速运动时可提高跟随速度。丢失后新建的轨迹不能继承另一人的平滑状态。

依据平滑参数构造扩展人像区域，保留头发、下巴以及头顶空间。单纯把紧贴五官的人脸框放大到固定方形，可能剪掉帽子空间。

### 4.2 对齐的人像裁剪

平滑处理时间变化；对齐处理空间差异。对齐通常通过平移、等比缩放和画面内旋转，将双眼等点映射到预设位置。

例如让输入图中的双眼大致水平、眼间距保持一致，网络看到的人像尺度更稳定。不要采用会改变脸型的任意非等比拉伸。二维对齐不会把真正的侧脸变成正脸，也不要求人为补出看不见的半张脸。

保存原图到生成画布的完整变换 T，包括裁剪、旋转、缩放和 padding。模型适配器若还改变输出尺寸，也必须计入变换。

$$
\tilde p_{\mathrm{canvas}}=T\tilde p_{\mathrm{frame}},
\qquad
\tilde p_{\mathrm{frame}}=T^{-1}\tilde p_{\mathrm{canvas}}.
$$

这里使用二维齐次坐标。生成的线描与输入画布对应，可把线描、遮罩和帽子整体逆变换回原图。若在已摆正的画布中绘制帽子，就不要再次应用原图的歪头角度，否则会重复旋转。

### 4.3 关键点与头部姿态

关键点是眼角、鼻尖、嘴角等位置；姿态是头部整体朝向：roll 为歪头，yaw 为左右转头，pitch 为抬头低头。表情是局部变化，不等于头部姿态。

五点足以完成基础对齐与画面内旋转。更稳定的转头和俯仰估计，需要密集关键点与标准三维人脸、相机参数，或复用模型输出的面部变换矩阵。MediaPipe 可作为 YOLO 之后的几何辅助。

姿态不直接回答“哪顶帽子更好看”，也不自动提供遮挡掩膜。它用于选择该帽子的视角素材、调整帽檐投影、确定局部层次；遮挡还需要头部轮廓或分割信息。

来源：[MediaPipe Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker)、[OpenCV PnP](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html)。

## 5. CNN 怎样生成线描：解码器究竟做什么

照片到线描可以写为：

$$
S=G_\theta(I)=D_\theta(E_\theta(I)).
$$

E 把照片转换为多通道空间特征，D 将这些特征组织为输出图的像素。解码器通过上采样恢复空间尺寸，通过学习到的卷积组合特征，输出哪里应为黑、哪里应为白以及过渡强度。

“扩大尺寸”本身不产生绘画知识；绘画取舍来自训练数据、训练目标与学习到的权重。最后一层把多通道表示投影为单通道图像，通常经 Sigmoid 或 Tanh 转为受限数值范围，再按模型约定映射为显示灰度。

转置卷积是可学习的上采样操作，不是编码器卷积的数学逆，也不是伪逆。另一路线是先插值上采样，再普通卷积。两者都必须有经过训练的权重才能完成特定映射。

上次采用“分类预训练特征＋程序化渲染”；本次调用完整的照片到线描生成器。不能随意把 YOLO 或 ResNet50 特征接进已有素描解码器：通道、尺度、分布与语义都可能不匹配。本次检测网络与素描网络是两个独立模型，靠裁剪图像连接。

作者训练过，不等于本作业要重新训练。推理时冻结整个生成器，输入照片即可获得栅格图，不需要再追踪骨架才算“生成”。

## 6. 三个成熟项目怎样解码

### 6.1 Informative Drawings：残差生成器

官方 Generator 的主要结构是输入卷积、两次 stride=2 下采样、若干残差块、两次转置卷积上采样、输出卷积与 Sigmoid。其测试脚本默认 n_blocks=3，而类构造默认值为 9；实例化必须匹配所下载检查点，不能只照类默认值加载。

以 256 方形输入说明张量形状：

| 阶段 | 张量，省略 batch |
| --- | --- |
| RGB 输入 | 3×256×256 |
| 初始卷积 | 64×256×256 |
| 第一次下采样 | 128×128×128 |
| 第二次下采样及残差处理 | 256×64×64 |
| 两次上采样 | 128×128×128 → 64×256×256 |
| 输出卷积与 Sigmoid | 1×256×256 |

作者采用非配对照片与线描进行学习，通过几何、语义及外观相关约束，使线条保留有用信息。几何目标要求从线描仍能恢复相关深度信息；语义目标比较照片与线描的 CLIP 表示。推理生成线稿只需要已训练的生成器，不能把这些训练辅助网络误当作每帧必经步骤。

这里的 residual block 并不意味着使用了 ImageNet 分类 ResNet50。它是为图像翻译训练的卷积生成网络。

来源：[论文与项目说明](https://carolineec.github.io/informative_drawings/)、[Generator 源码](https://github.com/carolineec/informative-drawings/blob/main/model.py)、[推理脚本](https://github.com/carolineec/informative-drawings/blob/main/test.py)。

### 6.2 U²-Net Portrait：嵌套 U 结构与多尺度融合

U²-Net 的外层是编码—解码结构，内部 RSU 模块也在多个尺度组织特征。解码时，上采样后的深层特征与同尺度浅层特征拼接：深层提供大范围结构，浅层补充空间定位。

多个阶段各自产生单通道侧输出，上采样到共同尺寸，再通过 1×1 卷积融合为最终输出。这样同时使用细节尺度与整体尺度，而不是只将最深的一张特征图放大。

必须加载人像绘画权重 u2net_portrait.pth。相同网络装入背景分割权重会做不同任务；网络形状并不决定它会画素描。官方人像推理脚本以 512 预处理，取融合输出后反相并归一化。先复现官方流程，再试更小尺寸；不能假定 256 与 512 等效。

视频适配还应观察逐图极值归一化是否导致明暗跳动。若调整这一后处理，需要单独比对，避免无意改变已验证的模型输出。

来源：[项目的人像绘画说明](https://github.com/xuebinqin/U-2-Net)、[网络实现](https://github.com/xuebinqin/U-2-Net/blob/master/model/u2net.py)、[人像推理脚本](https://github.com/xuebinqin/U-2-Net/blob/master/u2net_portrait_test.py)。

### 6.3 APDrawingGAN++：整体布局与局部五官协作

该项目同时生成全局结果和局部结果。其推理实现含双眼、鼻、嘴、头发、背景等局部分支，根据关键点与掩膜把局部结果放回整图，再由可学习的融合网络结合全局输出。不同配置使用残差或 U 形生成器，并有辅助分类／自编码修正分支。

这种设计承认“画头发”和“画眼睛”需要不同处理，因此显式分配网络能力。GAN 表示训练时有判别器帮助约束绘画分布；部署并不需要判别器给每帧打分，但检查点配置启用的生成与辅助网络仍需保留。

它更依赖规范的对齐、关键点和掩膜，所以作为学习和可选对照，不要求在主应用中同时维护第三套生成链路。

来源：[APDrawingGAN++ 官方仓库](https://github.com/yiranran/APDrawingGAN2)、[推理模型](https://github.com/yiranran/APDrawingGAN2/blob/master/models/test_model.py)、[网络定义](https://github.com/yiranran/APDrawingGAN2/blob/master/models/networks.py)。本次通过官方原始源码核对了局部与融合调用，未运行权重。

## 7. 二维帽子的定位、变换与遮挡

### 7.1 帽子库与选择

每顶帽子保存同画布的 RGBA 前层与后层，以及帽口中心 a、帽口左右锚点、推荐宽度比例 k、佩戴偏移、可用视角与许可来源。没有后层的帽子可以只用一层。

款式默认由用户选，并绑定 trackId；“自动合适”只做可解释的规则，例如在当前姿态下优先使用具有可用侧面素材的帽子。无需推断性别、身份或审美偏好。相同款式的视角切换设置滞回，避免角度临界点反复闪切。

### 7.2 基础相似变换

先在统一坐标系中取双眼中点 e、脸宽 w_f 与眼线角度 theta。设脸朝上的单位向量为 u，帽口目标中心 h=e+beta*w_f*u；beta 由素材校准。设素材帽口宽度 w_a，则缩放 s=k*w_f/w_a。

对帽子素材中的任意点 q：

$$
q'=h+sR(\theta)(q-a).
$$

它将帽口中心映射到佩戴位置，并同时缩放和旋转。两层共用这个基础变换，只有确有需要的帽檐透视或层内形变另设参数，不能各自独立跟踪、随意缩放，否则帽子会散开。

示意：帽口素材宽 200 px，目标脸宽 160 px，佩戴比例 1.25，则目标帽口宽为 200 px，缩放为 1；若脸宽增至 240 px，则缩放为 1.5。具体比例需要逐款校准。

### 7.3 不重复检测素描

原始照片估计几何 → 通过 T 映射到生成画布 → 绘制两层帽子 → 将完整结果通过 T 的逆映射回视频。

“生成前后”共享几何，不分别检测。“帽子前后层”共享基础姿态，只在遮挡上分开。输入与输出尺寸不同，补上尺度变换即可。

若生成器让额头边缘稍有变化，先调整裁剪和素材佩戴偏移；除非偏差严重且有证据，不额外加入素描人脸检测链路。

### 7.4 白纸不等于透明：必须有独立遮罩

线描通常是白底黑线，但白色脸颊仍然属于人像实体。直接令 alpha=1-S，会让帽子后层透过脸上的白色区域显示，造成错误。

定义独立人像占据遮罩 M：人像区域为 1，外部为 0。第一版可用关键点脸轮廓与估计头顶区域组成近似遮罩；若头发效果不够，再增加预训练分割。该遮罩不等于头发精细分割，不能宣传为准确遮挡。

在白纸底图 C0 上依次进行：

$$
C_1=A_bH_b+(1-A_b)C_0
$$

$$
C_2=MS+(1-M)C_1
$$

$$
C=A_fH_f+(1-A_f)C_2.
$$

Hb、Hf 是变换后的帽子后层与前层，Ab、Af 是各自透明度，S 是素描，M 包括人物内部的白色留白。所有量都在同一画布。图像和 alpha 同步变换，边界适度抗锯齿。

头部姿态提供朝向，遮罩提供“哪里被挡住”，素材分层提供“谁在前谁在后”。二维方案适合正面与中等转动；大侧脸需要对应视角素材，不能靠正面图片无限拉伸获得隐藏表面。

## 8. Web 实现与可视化

React＋TypeScript＋Vite 负责摄像头、控件与 Canvas；Python＋FastAPI 常驻加载检测器、选中的素描生成器及可选几何模型。先用 PyTorch 跑通，再按硬件考虑 ONNX Runtime／OpenVINO／CUDA；导出与精度一致性需实际检查。

浏览器通过二进制 WebSocket 发送压缩帧和 sessionId、frameId、configRevision。后端返回同帧合成图及人脸记录。只有一帧在途，忙时跳过；晚到的过期会话或旧配置结果丢弃。不同人的模型调用可按相同形状组成 batch，显存不足时分批。

保留多脸 ID 关联，但不把 trackId 当作身份识别。短暂丢失可保留配置，长时间丢失后回收；出现无法可靠关联的交叉遮挡时，允许重建 ID，避免强行认人。

界面布局：原图及检测框／戴帽线描画面并排；下方为按 ID 排列的个人肖像与帽子选择。调试开关显示五点、平滑裁剪框、帽口锚点和人像遮罩，帮助定位是检测、裁剪、生成还是合成的问题。原视频 FPS、处理 FPS、延迟和检出人数分别显示。

拍照冻结当前原图和全部人物配置，随后处理保存。结果必须来自同一冻结帧，不能拼接不同时间的个人缓存。初版个人肖像卡片是可靠展示方式；多人空间合成可采用纸面底图与独立人像遮罩，保留原画面位置。多人互相遮挡时的深度排序仅做近似，不以二维框宣称真实深度。

| 3. 实时多人 | 浏览器、常驻模型、ID 关联、几何平滑、单帧调度 | 静止不明显抖，运动不积压；进出画面能管理状态 |
| 4. 分层适配 | 前后帽层、独立占据遮罩；需要时加密集点和多视角 | 正面、歪头与中等侧转合成合理，无白脸漏帽 |
| 5. Web 交付 | 卡片与同帧多人显示、逐人换帽、冻结拍照、保存、异常反馈 | 摄像头到保存完整可演示 |
| 6. 验收与整理 | 修正边缘案例，测 1／2／4 人，记录配置与材料来源 | 提供运行说明、效果示例、关键参数和已知边界 |

阶段 6 已按本次决定调整，不再安排扩散或额外风格增强。前两模型二选一仍待试跑；检测器和应用栈已确定。

试跑优先覆盖正脸、眼镜、头发较多、暗光、轻侧脸及多人，视频检查静止、歪头、靠近、离开与交叉。关注人物辨识度、五官完整性、时间闪烁、帽子定位、遮挡和总延迟，不安排复杂人工评分。

先核实权重可下载、预处理匹配、黑白方向正确。Informative Drawings 从其默认 256 流程起步，U²-Net Portrait 先复现 512；尺寸调整作为单独实验。不要为了统一输入而跳过模型自身要求。

## 10. 下一步的最小实验

先输出一张对照板：原始人像、Informative Drawings、U²-Net Portrait、候选结果加一顶帽子。加入一段静止后歪头的视频，确认裁剪稳定和模型输出抖动程度。

选型时问两个问题：哪个模型更好地保留这个人的五官？在目标电脑、目标人数下能否及时更新？本次没有新的训练任务，重点是正确复用已有生成器，并把它与检测和几何组合起来。
